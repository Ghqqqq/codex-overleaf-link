逐节核验从文档检查代码，也从实际入口反查文档遗漏；当前可作为主要功能定位基线。完整性判断仍须限定到已记录的章节、调用链和证据范围，不能以链接数量或审阅轮数代替行为验证。

## 功能页的最低内容

一张功能页必须把用户触发、实际入口、权威状态和结果连接起来。固定记录以下内容，避免只罗列文件名：

1. 用户可见行为、范围和不变量。
2. 入口符号、主实现、组合位置、调用方和消费者。
3. 身份、数据转换、持久化位置及状态所有者。
4. 正常调用链；取消、超时、部分失败和恢复分支。
5. 按改动意图划分的联动清单。
6. 最近测试、真实交互验证及各自的证据边界。
7. 核验基线与尚未覆盖的情况。

系统架构解释各执行环境之间的协作；程序设计进一步解释函数和接口的真实调用。指南同时维护这两层，供后续任务选择足够小的修改范围。

## 文档维护约定

- 所有者、入口、协议、状态或加载方式发生变化时，在同一项修改中更新功能索引与受影响领域页。
- 常量和协议目录以源码为权威。文档只列解释所需的值，并链接实际定义，避免维护完整手工副本。
- 路径链接采用仓库相对形式，符号写在链接附近。行号只能辅助定位，不能替代符号与调用方。
- `Current behavior`（当前实现或源码事实）表示有源码依据；`Target contract`（目标契约或维护目标）表示应保持的要求；`Known gap`（已知差异）需要具体证据和范围。测试未执行、浏览器未验收单独标注。
- 已发布行为、当前 HEAD、本地候选改动分别记录。源码存在不能证明安装副本或浏览器已经加载它。
- 旧本地指南和交接可帮助追溯历史。新指南不依赖这些未随仓库分发的资料，原文中已过时的步骤不继续作为入口。
- Red-teaming 在这里指主动用反例挑战文档：寻找被忽略的入口、身份、时间顺序和恢复分支。审阅者先据指南形成定位，再核对真实调用链；修订后复查原反例。外部服务攻击或生产故障注入不属于这种文档审阅。
- 验证入口还需说明测试替换了哪些依赖。局部 helper 测试、源码字符串断言、模拟 transport 与真实装配覆盖不同边界，不能用同名测试文件推定整链保证。

只有本目录中明确列入 [Git 忽略例外](../../.gitignore)的文档进入版本管理范围；其他本地资料保持忽略。npm 分发内容仍由 [package.json](../../package.json) 的 `files` 管理，本轮不改变产品发布包。

## 按修改选择验证

文档改动检查内部及源码链接、符号、事实边界、忽略规则和独立定位任务。定位结果需要与真实源码交叉核对。

运行时代码改动按领域页选择最窄测试。运行器支持文件选择与只列出选择：

```sh
node scripts/run-tests.mjs --list test/ordinaryUndoRouting.test.js test/undoMirrorInvalidation.test.js
node scripts/run-tests.mjs test/ordinaryUndoRouting.test.js test/undoMirrorInvalidation.test.js
```

第一条仅列出测试；第二条执行测试。`npm run test:focus -- <文件>` 还会执行模块图检查，该检查会生成 content bundle。两者的副作用不同，见 [run-tests.mjs](../../scripts/run-tests.mjs) 与 [check-content-module-graph.mjs](../../scripts/check-content-module-graph.mjs)。

Chrome 加载、当前 Overleaf DOM、真实保存与刷新恢复需要对应交互证据。正式发布另有跨平台、打包、签名和更新验证，指南定位验收不能替代这些门槛。
